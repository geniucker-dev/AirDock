- Mirror AV diagnostics normalize the known NTP/Unix epoch offset and reject

- Runtime regressions verify independent audio/window/language updates survive a stale

  bars instead of UI chrome. Entry from settings/startup and page restoration,
  audio-only hiding, manual hide plus FLUSH and new-session auto-reveal are
  exercised under Xvfb. Hidden continuing frames do not wake the UI.
- Presentation tokens distinguish repeated video starts on the same RTSP
  connection from FLUSH and repeated SETUP. Tests cover the automatic-window
  return grace period, replacement sessions and manual restoration intent.
- Update regressions cover stable SemVer selection, official GitHub asset hashes,

  Iced interactions verify cached prompts, navigation, mirror validation without

## Windows package gate

The Windows workflow builds a pinned FFmpeg 8.1 playback-only LGPL DLL profile.
The packager resolves normal and delay-loaded DLL imports recursively, audits
actual loaded library APIs, forbids GPL/nonfree/NVENC/video encoder components,
requires HLS/TS/fMP4/HTTPS/TLS and hardware decoders, and includes corresponding
patched source plus build instructions. `NATIVE_AUDIT.json` records DLL hashes,
versions, flags and dependency closure. Packaged reconnect/fMP4 tests run with
native build directories removed from PATH.

Rust dependency notices cover the Windows dependency closure, including build
dependencies. Crates that omit workspace license texts use checked-in supplements
from the exact `.cargo_vcs_info.json` commit, with source URLs and SHA-256 hashes.
Packaging fails on missing texts or hash mismatches, and audits the copied texts.

Installer and portable ZIP originate from that same audited payload. Embedded
Windows icon/version resources are verified against AirDock's assets and Cargo
package identity. Credit is carried in README.md. ZIP entries and installed
files are checked against `PACKAGE_SHA256.json`; release checks
verify both asset hashes. Windows CI performs silent install, upgrade/repair,
obsolete-DLL cleanup, installed clean-PATH HDR mirror/fMP4 playback, reinstall
and uninstall. It preserves AirDock configuration, pairing identity and untracked
files and verifies autostart ownership. This validates packaging, not physical
tray interaction or default-device switching.

The updater executable is run with only its audited runtime DLL closure and a
clean PATH. Windows CI verifies portable and installed updates, waiting for the
parent process, automatic receiver restart, Unicode paths, unchanged configuration
and identity, removal of obsolete owned files and preservation of user files.
A locked DLL injects a mid-update failure and verifies restoration and restart of
the previous portable payload. These fixtures explicitly simulate version 0.0.0;
they do not claim historical binary compatibility or a physical tray test.

A package is validated only when that workflow and the final DLL audit succeed.
Linux development uses system FFmpeg; its license/configuration do not certify
Windows release DLLs.

## Protocol adapter extraction (2026-10-05)

Linux validation of this extraction passed formatting, warning-free Clippy,
80 library tests plus 2 updater tests, binary/example builds and the unchanged
dependency policy (539 packages; no retired GUI/audio dependencies). New tests
cover multiple backend lifecycle/failure isolation, duplicate registration,
cross-protocol ownership, reconnect/retirement, stale teardown, clock mapping
and local AirPlay shutdown with another protocol holding the playback lease.

Existing synthetic encrypted H.264/HEVC mirror, 10-bit/HDR mirror, RAOP/FLUSH,
13 reconnect scenarios, SIGINT/SIGTERM cleanup, HLS TS and fMP4 passed. Xvfb/
llvmpipe checks passed rendered mirroring, all 390 reconnect frames submitted,
receive/settings/hidden/restored/software-fallback activity and idle-CPU checks.
The shader oracle passed 115,616 checks with maximum error 1/255.

Three alternating Xvfb/llvmpipe runs per binary compared the exact pre-extraction
commit `7eeadf0` with this implementation, using the same 120-frame synthetic
low-resolution mirror input. Median GPU submissions were 120 for both; median
per-run processing P95 was 3.069 / 3.174 ms and P99 was 8.113 / 8.401 ms
(before / after). Submission-interval P95 was 34.761 / 34.494 ms and P99 was
36.468 / 40.214 ms. This short software-GPU smoke comparison does not establish
physical display FPS/latency, long-term drift, resource parity, Windows hardware
performance, or comparison against the original C++ receiver. Those require the
same-device physical acceptance described below.

## Remaining physical acceptance

No Windows/iPhone pair or physical audio/display hardware is attached to this
Linux workspace. Therefore the following are **pending**, not passed:

- iPhone mirror/HLS interoperability, real speaker stability, AV offset and drift.
- Default-device changes, unplug/replug and WASAPI latency/underrun recovery.
- Real DX12/Vulkan graphics drivers, GPU loss/reset, hybrid GPU copy/power behavior.
- Windows tray close/minimize/restore/autostart and mixed DPI monitors.
- Same-device reference playback/idle/tray performance and resource comparison.
- HTTPS playback against real AirPlay origin certificates/network behavior.

Software YUV download after hardware decode remains intentional. This version
uses shared UI/video GPU rendering but does not implement zero-copy native NV12
interop. P010/YUV420P10 and PQ/HLG now render through HDR-to-SDR mapping.
Native Windows HDR output, Dolby Vision/HDR10+ dynamic metadata processing and
12-bit/non-420/BT.2020 CL are not supported. See RUST_HDR.md. Video requires
a compatible wgpu adapter; software UI fallback supports controls/audio and
shows this limitation rather than displaying a blank successful video state.
